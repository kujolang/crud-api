# CRUD API repository hardening

Reviewed `main` from `6095239a2fadc29f582e0ead54e164b5630d2716`. The audited implementation ends at `7409a26be94f22ed83fbf9e7290938fef4f972b6`. The server-first showcase depends on Kujo and SQLite, with a Next.js playground. The review covered configuration, migrations, fixtures, SQL, concurrency, pagination, frontend fetches, authentication, CORS, logging, smoke tests, backup and restore, CI, and frontend dependencies. No model, MCP service, or paid upstream is involved.

The baseline passed the 17 backend checks on the exact published Kujo 1.8.1. Frontend baseline lint and build passed on Node 22.23.4. The build emitted a local disk-space warning while writing its webpack cache and produced all routes. The baseline lockfile had ten moderate dependency findings. The first backend attempts also hit the local disk quota. The successful baseline rerun used the unchanged source and exact runtime after reclaiming task-owned scratch.

| Priority | Finding | Fix and evidence |
| --- | --- | --- |
| P0 | Writes could outlive the checked revision, and seconds-resolution timestamps allowed a rapid update to keep the same token. | Update and delete predicates include the checked revision. Update timestamps advance on consecutive writes. Writes return rows from their own SQLite statements. The unchanged API returns one successful edit and one conflict for two edits from the same revision. |
| P0 | Startup seeding and migration could interleave across processes. | Startup acquires a database write transaction for schema and fixtures after setting its SQLite busy timeout. Two local instances started concurrently against one empty database and each reported five items. |
| P0 | Request configuration and metadata had unsafe fallbacks or global state. | Invalid security enums fail before opening the database. Request IDs are validated and passed explicitly to responses and logs. Auth and content headers use normalized singular lookups, auth comparison uses constant-time digest verification, and CORS advertises the custom auth header. JSON writes require objects and strings where the schema requires them. Size limits use the raw request byte count. |
| P0 | The per-client limiter did not use the actual Kujo peer field and its global dictionary had no expiry or capacity. | Per-peer admission is atomic in a bounded in-memory SQLite store with indexed expiry and a monotonic clock. Trusted proxy mode remains opt-in. Tests cover admission, retry metadata and direct versus proxy keys. |
| P0 | Regression tests could terminate unrelated listeners or remove the project's default data file. | Guarded fixtures report occupied ports, own their server PID, and validate the default database path in an isolated directory. |
| P1 | List queries repeated sixteen filter branches and advertised a continuation after a full final cursor page. | Build SQL from a fixed allowlist of predicates with bound values, use decoded query data, and look ahead one row for cursor continuation. Existing offset paging, sort order and totals are preserved. |
| P1 | The playground could use a stale list response or wait indefinitely on a request. | Add API deadlines, reject invalid successful JSON, cancel superseded reads, and load items independently of projects. The frontend retains its explicit local token storage control. |
| P1 | Runtime and lint lock dependencies had advisories. The SBOM command floated and the secret gate could print matching lines. | Upgrade Next.js to 15.5.29 and use ESLint 9 with the flat Core Web Vitals config. Use a versioned SBOM CLI and keep gate output generic. The resulting lock audit reported zero findings. |

Twenty-seven paired read comparisons on Apple Silicon used the exact 1.8.1 interpreter and one synthetic 12,000-item SQLite fixture. The cases covered offset, combined filters with a title sort, and a filtered cursor page. Response data matched in every pair. The baseline median was 20.028 ms (9.976–28.471 ms) and the updated median was 16.672 ms (7.926–27.757 ms). No memory or token reduction was measured.

Routes, existing response field names, default loopback listener, database path, and documented settings remain supported. Request IDs outside the supported format are replaced. Numeric `updated_at` strings can carry fractional seconds, and clients must echo them exactly. The database changes are additive or temporary. Full project collection reads remain part of the existing showcase contract. No cross-repository change is required for this pass.

Verification passed with `KUJO_BIN=<runtime> make test` on the published Kujo 1.8.1 and a Kujo 1.10.0 debug build, `KUJO_BIN=<runtime> ./scripts/run-smoke-tests.sh`, the frontend's TypeScript checker, and an offline Node fetch contract fixture. `npm ci --dry-run` validated the lockfile and `npm audit --package-lock-only` returned zero findings. A clean Git archive also served the expected health result through default and interpreter entrypoints. The exact hosted run passed its clean frontend install, lint, production build, security gates, and backend checks.
